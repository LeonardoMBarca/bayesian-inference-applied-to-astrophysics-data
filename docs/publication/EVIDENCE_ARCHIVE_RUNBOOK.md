# Transitive evidence and local restoration

This is a byte-availability protocol, not another scientific experiment. No
MCMC, Silver, Gold, or historical report is regenerated by these commands.

`publication/validation/external_audit_closure_v1/transitive_inventory_final.json`
is a versioned graph rooted in both campaign registries, the protected baseline,
and the historical `tcc_evidence_v1` manifest. Its explicit handlers follow:

- campaign declarations, protocols, report sources and sealed completion files;
- every registered attempt, including rejected results and unsealed cancelled
  preparation files (newly inventoried partial files are labelled as such);
- observational preparation manifests to the full Silver and Gold CSV files,
  effective inference input, and original selected RAW FITS;
- baseline Gold/Silver manifest rows and their declared source dependencies;
- publication RAW acquisition records, their selected sources and selection;
- synthesis tables, figures, source references, and original source-code bytes.

The implementation does **not** search arbitrary JSON strings for apparent
paths. Unknown report schemas, conflicting scientific hashes, escaping paths,
symlinks/junctions, cycles, missing dependencies, and byte mismatches fail.
Windows long paths are opened with the native extended-length prefix rather
than being silently classified as missing. Paths persisted in the inventory
remain repository-relative POSIX paths.

Original code/documentation may have legitimately changed during review.
Only for explicitly allowed source/document domains, an exact recorded SHA-256
can resolve to a historical Git blob. The resolution records the commit/blob;
it does not claim that the lookup commit was the original execution commit.
RAW, inputs, traces, results, protocols and scientific artifacts never use this
fallback to hide a modified working file. An inventory verification receipt
also records any later source-code fallback to its frozen snapshot commit.

## Commands

Run from the repository root, with ordinary Python (the archive tool uses the
standard library only). Outputs use exclusive creation; choose a new audit or
bundle filename for a new inventory version.

```text
python scripts/publication_evidence_archive.py inventory --snapshot-commit 4022d16aded5d218d0921a72817ecd05da4df6f1 --inventory publication/validation/external_audit_closure_v1/transitive_inventory_final.json
python scripts/publication_evidence_archive.py verify --inventory publication/validation/external_audit_closure_v1/transitive_inventory_final.json
python scripts/publication_evidence_archive.py bundle --inventory publication/validation/external_audit_closure_v1/transitive_inventory_final.json --bundle ../publication-audit-local-20260930/evidence_v1.zip --bundle-manifest publication/validation/external_audit_closure_v1/local_bundle_manifest.json
```

The original ZIP was created from the first complete inventory. A later
schema review added two Git-provided baseline environment files without
changing any external ZIP member. Its final binding is
`local_bundle_manifest_final.json`, produced by checking every existing ZIP
member against `transitive_inventory_final.json`:

```text
python scripts/publication_evidence_archive.py rebind-bundle --inventory publication/validation/external_audit_closure_v1/transitive_inventory_final.json --bundle ../publication-audit-local-20260930/evidence_v1.zip --bundle-manifest publication/validation/external_audit_closure_v1/local_bundle_manifest_final.json
```

The earlier `local_bundle_manifest.json` is preserved as an engineering
intermediate and must not be used with the final inventory.

The ZIP contains only inventory files absent from ordinary Git tracking,
including excluded posterior traces and large intermediates. All members have
logical path, size and SHA-256 in the bundle manifest; its ID is the complete
ZIP SHA-256. The bundle is **local only**. No upload, DOI, public distribution
permission or durable archival guarantee is implied. Do not add this large ZIP
to ordinary Git. Retain a second verified copy before relying on it as backup.

Use an independent checkout (not a worktree sharing untracked working data):

```text
git -c core.longpaths=true clone --single-branch --branch publication-grade-validation https://github.com/LeonardoMBarca/bayesian-inference-applied-to-astrophysics-data.git ../publication-audit-local-20260930/checkout
python scripts/publication_evidence_archive.py restore --root ../publication-audit-local-20260930/checkout --inventory publication/validation/external_audit_closure_v1/transitive_inventory_final.json --bundle ../publication-audit-local-20260930/evidence_v1.zip --bundle-manifest publication/validation/external_audit_closure_v1/local_bundle_manifest_final.json --receipt publication/validation/external_audit_closure_v1/clean_checkout_restore.json
```

Restoration verifies bundle identity and each streamed member, refuses path
escape and unlisted/duplicate members, and never overwrites differing existing
files. Repeating restoration skips already matching files. Finally it checks
**every** inventory byte in the destination, including the Git-provided files.
A successful receipt establishes availability in that independent checkout;
it is not a claim that inference was rerun or tables were regenerated there.
On Windows, `core.longpaths=true` is required by some archive product names;
without it Git can clone the object database but fail to populate those files.

## Current release validator

```text
python scripts/validate_publication_release.py --audit-output publication/validation/external_audit_closure_v1/release_audit_v2.json
```

The current campaign registry dispatches to a campaign-aware validator. The
legacy `expected_runs` implementation is retained for historical fixtures, not
used as the denominator of the completed 117-job and 400-job campaigns.
The validator compares declarations, seeds, execution state, every preserved
attempt, completion seals, transitive inventory and v2 claim/artifact sources.

Exit classifications are machine-readable and deliberately distinct:

- `0 / passed`: reviewed release prerequisites are satisfied.
- `1 / blocked_public_release`: evidence integrity passed, but explicitly
  named public-release reviews/deposition prerequisites remain pending.
- `2 / invalid_evidence` or `validator_error`: unexpected missing/corrupt
  evidence or validator failure. This must never be treated as an expected
  scientific rejection or a successful release check.

Negative or rejected scientific outcomes are not integrity errors. A completed
study can support a negative claim without supporting physical recovery. The
v2 claim ledger and run-scoped authorizations constrain those uses separately.
The release review inventory requires source-bound evidence for citation,
privacy/secrets, third-party redistribution, external archive, exact scientific
environment, clean-room validation and remote CI. Missing reviews stay pending;
this audit does not invent rights, an archive DOI, or release approval.
